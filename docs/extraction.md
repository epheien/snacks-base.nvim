# Extracting `snacks-base.nvim` and `snacks-image.nvim`

This repository keeps the extraction workflow for splitting `Snacks.image` out
of `folke/snacks.nvim` into two standalone, mutually exclusive plugin packages.
The upstream `snacks.nvim` checkout should stay clean because it belongs to the
original project.

## Packages

- `snacks-base.nvim`
  - Generated at `build/snacks-base.nvim`.
  - Remote: `https://github.com/epheien/snacks-base.nvim`.
  - Provides the original `Snacks` global, minimal config helpers, `Snacks.util`,
    `Snacks.win`, `Snacks.health`, `Snacks.debug`, `Snacks.notify`, and the
    `Snacks.picker.util.tpl` shim used by the image module.

- `snacks-image.nvim`
  - Generated at `build/snacks-image.nvim`.
  - Remote: `https://github.com/epheien/snacks-image.nvim`.
  - Contains the original `lua/snacks/image/*`, image Tree-sitter queries,
    image docs, vimdoc, and image test fixtures.

The split packages intentionally keep the original `snacks.*` Lua namespace and
`_G.Snacks`. They are intended to be used instead of the full `snacks.nvim`, not
alongside it.

## Script

Use [extract-image.lua](../scripts/extract-image.lua).

In the local layout where this repository lives at
`SOURCE/build/snacks-base.nvim`, the script can infer both the upstream source
root and target root:

```sh
./scripts/extract-image.lua --force
```

For a standalone clone of `snacks-base.nvim`, pass the upstream source root and
target root explicitly:

```sh
./scripts/extract-image.lua /path/to/folke/snacks.nvim /path/to/output --force
```

The target root should contain both child repositories:

```text
/path/to/output/snacks-base.nvim
/path/to/output/snacks-image.nvim
```

You can also use named options:

```sh
./scripts/extract-image.lua --source /path/to/folke/snacks.nvim --target /path/to/output --force
```

The script writes `.snacks-extracted-generated` into each generated package and
will only replace an existing directory when that marker exists. On regeneration
it preserves each child repository's `.git` directory, so remotes and local
commit history survive `--force`. It also writes this document and the extraction
script back into `snacks-base.nvim`.

## Update Workflow

1. Update the upstream source repo:

```sh
git fetch origin main
git switch main
git pull --ff-only
```

2. Regenerate the split packages from `snacks-base.nvim`:

```sh
cd /Users/eph/myconf/vim/lazy/snacks.nvim/build/snacks-base.nvim
./scripts/extract-image.lua --force
```

3. Verify the generated packages load together:

```sh
nvim --headless -u NONE -i NONE \
  +'set rtp^=/Users/eph/myconf/vim/lazy/snacks.nvim/build/snacks-base.nvim' \
  +'set rtp^=/Users/eph/myconf/vim/lazy/snacks.nvim/build/snacks-image.nvim' \
  +'lua local Snacks=require("snacks"); Snacks.setup({ image = { doc = { enabled = false } } }); for _,m in ipairs({"snacks","snacks.util","snacks.win","snacks.health","snacks.debug","snacks.notify","snacks.picker","snacks.picker.util","snacks.picker.util.async","snacks.image","snacks.image.terminal","snacks.image.convert","snacks.image.image","snacks.image.placement","snacks.image.buf","snacks.image.doc","snacks.image.inline"}) do require(m) end; print("ok")' \
  +qa
```

4. Commit each child repository:

```sh
cd /Users/eph/myconf/vim/lazy/snacks.nvim/build/snacks-base.nvim
git status --short
git add .
git commit -m "Update extracted snacks base"
git push

cd /Users/eph/myconf/vim/lazy/snacks.nvim/build/snacks-image.nvim
git status --short
git add .
git commit -m "Update extracted snacks image"
git push
```

## Notes

- Do not run the split plugins together with full `snacks.nvim`; their Lua module
  names and global `Snacks` namespace intentionally overlap.
- `snacks-image.nvim` requires `snacks-base.nvim` earlier on `runtimepath`.
- The generated `.gitignore` excludes `.DS_Store` and `doc/tags`.
- `.snacks-extracted-generated` is intentionally committed. It is the safety
  marker that allows the extraction script to overwrite generated contents.
- If new upstream image code starts depending on more non-image modules, add the
  smallest required shim or copied module to `snacks-base.nvim` in
  `scripts/extract-image.lua`, then regenerate.
- Keep this workflow documentation and extraction script in `snacks-base.nvim`,
  not in the upstream `snacks.nvim` checkout.
- If generated vimdocs change upstream, keep `doc/snacks.nvim-image.txt` in the
  image package. `doc/tags` should be regenerated by users or package managers,
  not committed.
